# Technical audit, 11 November 2026

Scope: branch `feat/simple-job-discovery` at `9a30cd9` (55 commits ahead of `origin/main`,
never pushed), both local databases, docs, tests, config.

## What exists

- Python 3.12 modular monolith: FastAPI + Jinja + vanilla JS, SQLAlchemy 2, Alembic (17
  migrations), SQLite, an in-process worker with a DB-backed task queue. ~19,200 lines of
  source, 765 tests, ruff and strict mypy clean.
- Seven source adapters (Greenhouse, Lever, Ashby, SmartRecruiters, Remotive, Jobicy, We Work
  Remotely) plus manual intake; a polite fetcher (timeouts, backoff, per-host rate limits,
  auto-disable on 403/429).
- Ingestion with provenance, revision history, separate published / first-seen / last-seen
  times, and four-step dedupe.
- Deterministic lane matching with pass / fail / unknown hard filters.
- Evidence-linked resume tailoring to LaTeX/PDF, application records, approval gates,
  referral paths, interview plans, market briefs, analytics, backups, a local LLM gateway.

## Findings

1. **Wrong coverage (root cause).** The watchlist is late-stage fintech and infrastructure
   companies. They rarely post entry-level analyst roles, and the candidate's Tier-1 targets
   (State Street, Fidelity, Wellington, consultancies) are on Workday, which had no adapter.
2. **No employer-level sponsorship evidence.** Only posting text was read, so most jobs had
   no signal and nothing separated a plausible employer from an implausible one.
3. **Per-lane verdicts.** Eight lanes multiplied every job into eight results; the candidate
   never saw one clear answer per job.
4. **Scope sprawl.** Missions, agent runs, market briefs and a local-model runtime consumed
   most of the activity while the core funnel stayed empty. `.tools/` holds 4.3 GB (a GGUF
   model, Ollama, caches); 13 backups hold 377 MB.
5. **Two databases.** `data/careeros.db` (173 MB, stale since 6 Nov) and
   `data/candidate-v2/careeros.db` (396 MB, live). The first appears abandoned.
6. **Unpushed work.** 55 commits exist only on this Mac.
7. **The GitHub repository is public.** Nothing sensitive is committed (`.env`, `data/` and
   `config/sources.toml` are ignored), but the mission spec contains personal context and
   must stay untracked.

## Security review

- No secrets in git history for the audited branch; `.env` is ignored and holds only local
  settings. Server refuses non-localhost binds without an explicit override. CSRF and a
  strict Content-Security-Policy are in place.
- Job text is treated as data: it is regex-parsed and HTML-escaped on render, and is never
  passed to a model on the discovery path, so it cannot inject instructions there.
- Risk to manage: the phone number and email in the profile live in the SQLite file,
  unencrypted, on a personal laptop. Acceptable for local-first; do not sync `data/` to a
  shared location.

## Preserve / refactor / replace

| Area | Decision |
|---|---|
| Fetcher, adapters, ingestion, dedupe, provenance, migrations, tests | Preserve |
| Profile, evidence base, resume tailoring, application records, approvals | Preserve (phase 2 builds on them) |
| Source registry | Extended (Workday, community feed, harvester) |
| Sponsorship display cache (`job.sponsorship_status`) | Superseded by evidence levels; remove after cutover |
| Lane matcher and New Jobs inbox | Superseded by the verdict engine and Today; remove after a week of parallel use |
| Missions, market briefs, local-model runtime | Freeze. Remove unless a phase needs them |
